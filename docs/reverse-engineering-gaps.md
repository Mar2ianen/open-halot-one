# HALOT-ONE reverse-engineering gap map

This is the working closure list for a replacement host/backend on the inspected CL-60. “Closed” means the software behavior is recovered from the installed image or observed during an ordinary print; it does not imply electrical or physical verification. Binary captures and per-device data remain in the private output directory, not this repository.

## Acceptance gates for a normal-print port

- Every STM32 request, reply, timeout, and state transition used during a complete job has a documented host and firmware path.
- The layer image transform is proven from source file to physical panel orientation and grayscale mapping; frame change is synchronized to a known event.
- Movement, homing, endstops, UV enable/duty, fan, pause/resume/cancel, and fault-off behavior have verified units, pin destinations, and safe failure behavior.
- The open job format and metadata path reproduce stock layer order, thickness, exposures, delays, masks, and progress.
- A host image boots with a tested rollback route, and the stock recovery path remains intact until repeated complete jobs pass.

Until those gates are met, the Rust adapter is an analysis prototype and not a printer backend.
